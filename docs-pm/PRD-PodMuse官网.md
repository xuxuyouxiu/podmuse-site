# PRD：PodMuse 官网（单页滚动）

**版本**：v1.0
**作者**：PodMuse
**日期**：2026-08-14
**状态**：草稿

## 1. 背景与目标

### 1.1 背景
PodMuse 桌面应用已迭代至 v1.45.x，功能成熟，但缺少对外官网。用户持有域名、无服务器、预算为零，官网用静态网页 + GitHub Pages 免费托管实现，视觉要求「高级感」：**白色底 + 科技紫 + 玻璃拟态 + 高级动画**（GSAP）。

### 1.2 目标用户

| 用户角色 | 特征 | 核心诉求 | 使用场景 |
| --- | --- | --- | --- |
| 播客/视频重度听众 | B站、小宇宙用户，听得多忘得快 | 把听过的内容沉淀成笔记 | 手机/电脑浏览器访问官网 |
| 知识管理人群 | 用 Obsidian/Notion 记笔记 | 自动生成结构化笔记、实体互链 | 通勤/办公时浏览 |
| 路过的访客 | GitHub/抖音/朋友推荐而来 | 快速搞懂是什么、值不值得装 | 碎片时间扫一眼 |

### 1.3 业务目标与成功指标

| 目标 | 衡量指标 | 目标值 | 监测方式 |
| --- | --- | --- | --- |
| 提升下载转化 | 官网访问 → 点击下载比例 | ≥ 20% | GitHub Releases 下载量（可后接统计） |
| 讲清产品价值 | 首屏停留 + 滚动深度 | 访客滚动到功能区 | 无埋点时以页面设计质量衡量 |
| 打赏 | 打赏次数 | 有即可 | 收款码收款记录 |

## 2. 功能需求

### 2.0 整体结构（单页滚动）

```
顶部导航（固定，毛玻璃）
  ├ 品牌 logo + 导航锚点：功能 / 下载 / 支持
  └ GitHub 链接
① Hero 首屏
② 为什么 PodMuse（3 个痛点→方案）
③ 功能展示（6 卡片）
④ 处理流程（链接→笔记 3 步示意）
⑤ 下载区（版本号 + 下载按钮）
⑥ 打赏区（收款码）
⑦ 页脚
```

### 2.1 Hero 首屏（P0）

- **内容**：PodMuse 名称 + 一句价值主张 + 副标题 + 主 CTA「免费下载」+ 次 CTA「了解更多」
- **动效**：入场文字逐行浮现；背景紫/粉渐变光斑缓慢流动（模糊大圆斑）；底部音波波形装饰
- **交互**：CTA 点击滚动到下载区 / 打开 Releases
- **边界**：加载失败仍显示静态版式（动画为增强，非依赖）

### 2.2 为什么 PodMuse（P0）

- 3 张玻璃卡片：不再回听 / 知识互链 / 随时可问，各配一句场景描述
- 动效：滚动进入视口时依次上浮

### 2.3 功能展示（P0）

- 6 张卡片（2×3 网格）：一键处理 / AI 结构化笔记 / 知识库互链 / 智能订阅 / 知识问答 / 导出分享
- 每张：图标 + 功能名 + 一句话说明，**无技术黑话**（不出现 RSS/Whisper/markdown 等）
- 动效：卡片滚动浮现（stagger）；鼠标悬停轻微上浮 + 阴影加深

### 2.4 处理流程（P0）

- 3 步横向示意：粘贴链接 → AI 转写提炼 → 笔记入知识库，步骤间连线动画
- 动效：滚动进入时步骤依次点亮

### 2.5 下载区（P0）

- 最新版本号（可静态写在页面里，与发布流程同步更新）+ 大按钮「下载 Windows 版」
- 备选：GitHub Releases 链接 + 项目仓库链接

### 2.6 打赏区（P1）

- 委婉文案 + 微信/支付宝收款码并排（≥200px 原比例，复用应用内同款素材）

### 2.7 导航与页脚（P1）

- 顶部固定导航：毛玻璃白底；滚动后加阴影；移动端折叠为汉堡菜单
- 页脚：版权 © 2026 PodMuse · GitHub · 邮箱

## 3. 非功能需求

| 项 | 要求 |
| --- | --- |
| 性能 | 无框架；GSAP CDN 单文件；首屏 LCP < 2.5s；图片懒加载 |
| 响应式 | 桌面 1280 优先；移动端 375px 布局降级（网格转单列、导航折叠） |
| 无障碍 | `prefers-reduced-motion` 时关闭大幅动画；语义化标签；按钮可键盘操作 |
| 兼容 | Chrome / Edge / Safari 最新两个大版本 |
| SEO | title/description/og 标签；语义化 h1-h3 |
| 安全 | 纯静态无表单，无注入面 |

## 4. 上线计划

1. 开发完成 → 本地浏览器全功能验证
2. 推送到 GitHub 新仓库（或 PodMuse 仓库 gh-pages 分支）
3. 开启 GitHub Pages → 用 `username.github.io/repo` 临时验证
4. 域名 CNAME 绑定（需用户提供域名与 DNS 管理商）→ HTTPS 生效
5. 交付：域名可访问 + 手机/桌面双端检查

## 5. 风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| GitHub Pages 国内访问慢 | 访客打开慢 | 全站体积控制 < 1MB；后续可切 Cloudflare Pages |
| 域名未备案 | 无法用国内 CDN | GitHub Pages 托管不受影响（走海外） |
| 版本号更新滞后 | 下载页显示旧版本 | 上线流程中把「更新官网版本号」并入发布检查单 |
| GSAP CDN 被墙 | 动画失效 | 资源本地化打包进仓库，不走 CDN |
