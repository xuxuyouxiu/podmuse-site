# 用户故事 — PodMuse 官网

**需求 ID：** ICE 82（排名 1）
**版本：** v1.0
**状态：** 规划中
**创建日期：** 2026-08-14

---

## 背景与现状

- PodMuse 已有成熟桌面应用（v1.45.x），但**没有官网**，唯一的对外入口是 GitHub 仓库页面
- 用户只有域名、无服务器、不想花钱 → 静态网页 + GitHub Pages 免费托管
- 现有 README 偏开发者视角，普通用户看不懂
- **目标**：一个「高级感」产品官网——白色底 + 科技紫玻璃拟态 + 高级动画
- **明确不做**：用户系统、后台管理、动态数据库（无服务器场景不需要）

## 用户画像（摘要）

| 维度 | 内容 |
| --- | --- |
| 目标用户 | ① 播客/视频重度听众（B站、小宇宙用户），想沉淀笔记；② 知识管理人群（Obsidian/Notion 用户）；③ 路过官网的 GitHub/抖音访客 |
| 核心痛点 | 听过的节目记不住；不知道这软件能干什么、值不值得下载 |
| 使用场景 | 在手机/电脑浏览器里打开官网，看介绍 → 决定下载 |
| 用户目标 | 30 秒内看懂「这是什么、能帮我干什么」→ 一键下载 |
| 付费意愿 | 免费下载软件；打赏自愿（官网放收款码） |

## US-001 首屏 Hero（P0）

**作为** 第一次访问官网的访客，**我想** 在首屏看到一句讲清楚产品价值的话 + 明显的下载按钮，**以便** 30 秒内决定要不要下载。

**验收标准：**

1. 首屏包含：产品名 PodMuse + 一句话价值主张（非「写入 Obsidian」式表述）+ 主按钮「免费下载」
2. 主按钮点击 → GitHub Releases 最新版本下载页（或经官网版本检测后跳转）
3. 首屏背景有高级动效（渐变光斑流动），白色底
4. 移动端首屏内容不溢出、按钮可点

## US-002 功能展示区（P0）

**作为** 访客，**我想** 用最少的时间了解核心功能，**以便** 判断它是否解决我的问题。

**验收标准：**

1. 展示 4-6 个核心功能块（一键处理 / AI 结构化笔记 / 知识库互链 / 问答 / 订阅 / 导出），图标+一句话说明
2. 滚动到该区域时逐块浮现动画（ScrollTrigger）
3. 不出现技术黑话（RSS、Whisper 等内部名词不暴露给访客）

## US-003 下载区（P0）

**作为** 访客，**我想** 知道最新版本号并能直接下载安装包，**以便** 快速安装。

**验收标准：**

1. 显示最新版本号（与 GitHub Releases 同步）
2. 下载按钮直达安装包（Windows exe）
3. 提供 GitHub 仓库链接作为备选

## US-004 打赏区（P1）

**作为** 觉得软件有用的用户，**我想** 在官网看到打赏入口，**以便** 支持作者。

**验收标准：**

1. 委婉文案 + 微信/支付宝收款码并排
2. 收款码清晰可扫（≥200px，保持原比例）

## US-005 导航与页脚（P1）

**作为** 访客，**我想** 页面有清晰导航和联系方式，**以便** 快速跳转和联系作者。

**验收标准：**

1. 顶部导航：首页锚点（功能/下载/关于）+ GitHub 链接
2. 页脚：版权、GitHub、邮箱联系方式

## 非功能需求

1. **性能**：首屏 LCP < 2.5s（GSAP 按需加载，不引重型框架）
2. **响应式**：桌面 1280px 优先，移动端 375px 不破版
3. **无障碍**：按钮/链接可键盘操作；动画尊重 `prefers-reduced-motion`
4. **SEO**：标题/描述 meta 齐全，中文关键词（播客笔记、AI 笔记）

## 已排除

- 深色主题（用户明确要白底）
- 用户注册/登录、评论系统
- 多语言切换（v1.0 中文为主，英文版后续再说——待确认）
- 后台管理界面
